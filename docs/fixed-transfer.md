# 固定搬运场景与接口示例

任务原点是 `[0.3,-1.2,1.1,-1.1,1.0,0.2]` rad 的已检查安全姿态，不是编码器零位或六关节全零。流程为原点→抓取→避障中间点→放置→返回。配置在 `config/fixed-transfer.v1.json`；所有位姿、关节与时间使用 m、rad、s，关节顺序 J1–J6。

唯一控制周期继续取自 `config/cartesian-planning.v1.json:sample_period_s`，规划／连续 IK／插补／控制／反馈均为 20 ms，物理内部 4×5 ms 子步。整个任务只有一个整数场景时钟；每段使用其局部时间视图进行认证轨迹求值，不另启时钟。阶段结束与开始的反馈允许在同一个全局拍号发生，日志带阶段名和段内拍号；实际运动写入必须全局拍号严格连续、每拍唯一。

抓取使用理想固定约束，载荷为 30 g、边长 16 mm 方块，工具坐标系偏移 `[0,0,0.1]` m。抓取前检查实际物体和抓取点距离不超过 3 mm；附着后实际约束位置误差不超过 3 mm。放置后移除抓取约束并将物体切换为静态虚拟料位，保留释放时实际位姿，不把物体传送到目标。落位误差与返回后物体保持误差均不超过 3 mm；关节返回误差不超过 0.001 rad。没有真实夹爪、摩擦力闭合或料台支撑模型，不能据此证明真实硬件抓取可靠性。

障碍位于抓取与放置物体中心的中点。必须先验证携物直达路径返回 `3003`、`data=null`；再走抬高 65 mm 的中间点。每段均从实际反馈起点重新规划和完整认证，执行入口继续验证证书和同周期。携物碰撞检查包含方块对障碍、方块对机器人、整臂及自碰撞；连续运动包络半径增加工具偏移及方块顶点半径。附着时只排除工具与 wrist_3 相邻装配的预期接触，列表随场景元数据保存。动力学客户端另检查实际物体间隙和约束误差。计划连续证明不等于对实际跟踪误差管道的连续证明。

六轴位置 C PID 输出限幅速度，PyBullet 执行速度内环。每段从实际反馈位姿出发，用 shortest SLERP 回到固定目标姿态，处理实际跟踪造成的微小姿态偏差，仍重新完整认证；不把实际起点替换为理想值。阶段切换时速度目标归零，后一段首条实际速度命令也检查加速度限幅。失败停止推进仿真、保留此前日志和错误现场；只成功认证的轨迹能进入执行器。

## 独立 C 编译与调用

冻结运动学 ABI 的支持平台仍为 Linux x86_64、LP64、小端 binary64。`core/CMakeLists.txt` 是仅含 C 的入口，不查找 Python、不启用 C++，三个核心库只依赖系统 C／数学库。它与原根 CMake 构建并存，不改变现有 ABI。

```sh
cmake -S core -B build-core -DCMAKE_BUILD_TYPE=Release
cmake --build build-core --parallel 2
ctest --test-dir build-core --output-on-failure
cmake --install build-core --prefix "$PWD/build-core/install"
cc -std=c11 -Ibuild-core/install/include examples/core_api_demo.c \
  -Lbuild-core/install/lib -Wl,-rpath,"$PWD/build-core/install/lib" \
  -lrobot_contract -lrobot_planning -lrobot_control -lm -o build-core/external-consumer
./build-core/external-consumer
```

`examples/core_api_demo.c` 是完整外部消费者：构造明确的标准 DH 示例模型→FK→解析 IK→关节规划／求值→PID 加速度／速度前馈接口调用，并验证缺模型返回 `1004`、输出缓冲区不变。示例配置 Ka=0、Kv=1、输出 rad/s；其模型是教学夹具，实际搬运使用审计后的 `models/ur5/kinematics.json`。C 关节规划结果本身不具备 Python 层完整碰撞／TCP 认证，示例输出 `executable:false`，不能直接下发设备。

头文件契约为 `include/robot_kinematics.h`、`robot_planning.h`、`robot_control.h`。每次先检查返回码，非零不读取旧输出；状态与输出缓冲区由调用者持有。FK 矩阵为行优先 double[16]，IK 参数长度分别为 16、6；PID 状态每段显式复位，配置时间必须与当前周期一致。

## Python 集成与演示

```sh
python -m pip install numpy==1.26.4 pybullet==3.2.7 Pillow==11.0.0 imageio-ffmpeg==0.6.0
python examples/fixed_transfer_demo.py --output results/fixed-transfer
```

这个入口调用 `scripts/verify_fixed_transfer.py`，库路径可用 `--library`、`--planning-library`、`--control-library` 显式指定。集成顺序可直接参考该脚本的 `main`：加载共享周期→场景和载荷→从反馈构造起点→`CartesianPlanner.plan`→`SixAxisExecutor.run`→抓放状态变化后重新认证下一段。`PayloadScene` 隔离碰撞模型与物理客户端，`SegmentClock` 只映射唯一时钟。

结果目录保存：每段完整规划／IK／认证 JSON、每拍控制 CSV、原始物体反馈和全局区间指令 CSV、异常 JSON、状态事件与验收指标 `report.json`、纯 C 构建／安装／测试及动态依赖日志、`demo.mp4` 与五个阶段 PNG。阶段末的速度目标归零不会推进物理时间，单独记录在 `zero-targets.csv`，不混入全局运动区间计数。视频由实际物理状态采样，10 fps、正常仿真速度，右下角为物体与障碍近景。视频不是轨迹示意动画。所有失败也上传已有证据，不能用最终截图代替完整记录。

## 改进 APF 与传统 APF：固定搬运量化对照

### 实验范围与公平性

本节是冻结版本后的增补实验，原单次搬运入口及 `v1.0.0-internship` 标签不变。对比的两条链路是仓库现有传统 APF（`static_apf`＋逐途经点静止定时），以及子目标引导 APF＋连续碰撞约束平滑／捷径＋重新定时（`improved_plan`）。传统基线本身已有目标距离衰减斥力、全臂／自碰撞及完整认证，不代表所有教材 APF 变体。

两者都从相同原点完成抓取→已给定避障中间点→放置→返回；采用原配置中的 30 g 方块、相同障碍、工具偏移、PID 参数、驱动力、重力和末段 0.5 s 保持。四个目标关节状态由同一离线 IK 配方生成并保存，两方法共用。这里比较关节空间 APF 路径，约束业务端点位姿与导数／碰撞，不要求中途跟随原笛卡尔直线／SLERP 曲线。因此本表不是把原来人工设时的 54 s 演示当作传统 APF，也不证明自动发现业务中间点的收益。

配置为 `config/fixed-transfer-apf.v1.json`。从共享配置派生同一份实验限值，规划速度为 0.04 rad/s、加速度为 0.4 rad/s²，控制仍限于 0.05 rad/s、0.5 rad/s²；TCP 限值保持原配置，规划／控制／反馈同为 20 ms。两者每阶段时长预算均为 60 s、节点上限 3001；这是实验预算，不修改原入口的 30 s／2001 节点配置。APF 每次调用仍为 160 次迭代、最大关节步长 0.02 rad，改进方法最多尝试 27 个子目标，其额外调用、平滑与两轮认证全部计入在线规划耗时。压缩系数为 0.8，缩时后必须重新完整认证；两者失败均不执行部分轨迹。

各预热一次首段规划，再交替执行三组配对：传统→改进、改进→传统、传统→改进。每次使用新建但初始条件相同的物理场景，全部六次运行真实闭环、抓放和返回，逐段完整认证，保存逐拍数据和视频。计时范围是规划函数进入至返回；不含离线共享 IK、场景构建、路径统计、序列化和录影。分位数采用 h=(n−1)p 线性插值，失败样本不删去；无成功时成功轨迹指标为 null。

逐次结果也保留：传统三次均为 4389 个运动区间、87.78 s；改进三次均为 2336 个区间、46.72 s。配对串行成本分别节省 36.099、35.816、36.161 s；三组均成功，没有剔除失败样本。所有成功阶段均通过关节／TCP 连续导数、全臂／自碰撞和携物间隙认证，并通过执行器的统一时钟、实际反馈和指令限幅检查。最低实际间隙均大于 3 mm；放置／保持和附着误差均小于 3 mm，返回误差小于 0.001 rad。改进后放置、返回与附着误差有小幅增加，不能称为精度全面提升。

### 能体现的业务价值与代价

在这条固定搬运配方中，平滑和捷径去掉了 55 个算法内部停点，TCP 路径仅缩短约 4.49%，而运动与保持时间减少 41.06 s（46.78%）。因此主要收益来自减少碎片化启停和重新分配时间，而非单靠缩短距离。这里的启停是计划中的静止节点，不等价于已测得电机冲击或磨损。

计算代价同样明确：完整规划平均增加 5.035 s（28.16%）。把这一开销计入后，串行周期代理仍平均减少 36.025 s（34.10%）；按本次全部尝试的累计成本，产能代理由 34.072 增至 51.699 件/h，约增加 51.73%。计算式为“3600×完成件数÷全部尝试的（仿真运动／保持时间＋在线规划耗时）之和”；失败也进入分母，失败次数进入成功率。若存在失败后的人工处理、恢复或重新上料，应额外计时，本实验不把这些成本假设为已验证。

以上说明在既定安全和精度阈值内，减少中间停点可以抵消额外规划开销，为重复搬运缩短周期提供仿真证据。它不是设备实测产能：未计上／下料、通讯、标定、真实夹爪与摩擦、故障恢复和硬实时调度；没有测量电流或能耗，不能据此声称节能、磨损降低或真实工厂收益。三个确定性配对只支持本场景的观察结果，不证明统计普适性、成功率提高、全局最优或更强自动避障能力。若配方能够长期离线复用，可另做缓存后的整线节拍试验，本表仍完整计入每次在线规划。
