# 六轴低速闭环联调

入口为 `SixAxisExecutor.run(result)`：CartesianPlanner 生成固定直线和 SLERP 姿态路径，逐节点连续逆解，经完整关节、TCP 导数、整臂及自碰撞认证，执行门验证当前进程证书、配置、模型、动态库和场景后才调用运行器。运行器按原认证多项式插补 q、qd、qdd，不重新拟合。候选、篡改或认证失败均无运动指令。

统一周期唯一来源为 `config/cartesian-planning.v1.json` 的 `sample_period_s=0.02` s。`load_execution_config` 读取 `config/six-axis-execution.v1.json` 的 `planning_config` 引用，并将这一周期注入 PID、控制时钟和反馈。执行配置不再重复声明 dt；如另行声明与规划不一致的 dt，返回 1006。规划／逆解节点、插补、控制和反馈均为 20 ms；物理积分内部使用 4 个 5 ms 子步。唯一整数 tick 决定全部仿真时间：读本拍反馈→插补→六轴 C PID→下发速度→4 个物理子步→tick 加一。反馈必须与当前 tick 和时间严格匹配。不是墙钟实时调度器；单拍处理耗时及超过 20 ms 的次数单独记录，不作为真实机器人实时性证明。

六轴位置外环采用现有 C PID，速度前馈 Kv=1、Ka=0，输出单位 rad/s，内环为 PyBullet 速度伺服。Kp=4/s、Ki=0.2/s²、Kd=0，积分项限制 ±0.01 rad/s。速度请求限制 ±0.05 rad/s，相邻速度请求差不超过 0.5×0.02 rad/s。反馈速度阈值 0.06 rad/s，跟踪误差阈值 0.03 rad。重力 [0,0,-9.81] m/s²，固定基座、无附加载荷，六轴伺服力矩上限 [150,150,150,28,28,28] Nm；这些是仿真配置，不是电机实测。控制链没有采用上一轮单关节试验的惯量前馈参数。

固定起点 [0.3,-1.2,1.1,-1.1,1.0,0.2] rad；TCP 平移 [0.01,0.004,0.006] m 并绕 base Z 转 0.015 rad，6 s 完成、保持 2 s、重复两次。轨迹必须六轴均发生运动，末端保持后最大关节误差小于 0.001 rad。轨迹认证用碰撞客户端与动力学客户端分开，避免碰撞检查重置物理状态；每拍实际反馈也检查整臂及自碰撞，实际运动的离散碰撞检查不等同于跟踪误差管道的连续碰撞证明。

异常判据：

|类别|判据|返回码|
|---|---|---|
|时序|重复、丢拍、逆序；反馈序号或时间与本拍不一致|1006|
|指令跳变|相邻参考位置差 >0.05×dt+1e-8 rad，参考速度差或速度命令差 >0.5×dt+1e-8 rad/s|4001|
|低速包络超限|参考速度 >0.05 rad/s、加速度 >0.5 rad/s²；反馈位置越关节限位|3002|
|控制异常|反馈缺失/非有限、反馈速度 >0.06 rad/s、误差 >0.03 rad、控制器失败/非有限/超限|4001|
|碰撞|实际反馈整臂/自碰撞距离不满足场景间隙|3003|
|认证入口|候选或被修改的轨迹|3001|
|缺配置|执行配置必要字段缺失|1004|

执行器通过认证门后，在读取反馈和发送任何运动指令前，检查认证周期、规划与插补节点时间网格、IK 节点编号和时间、PID、时钟及物理反馈周期均与同一周期一致；任何失配均返回 1006，并记录 cycle_consistency 阶段，运动写入为零。

异常检测在本拍运动写入前进行。每拍新建空观测上下文，observed_clock、observed_feedback、observed_reference、raw_control_outputs、observed_command、validated_command 未获取时均为 JSON null。控制器完整返回值及原始输出在校验前保存，observed_command 是本拍原始输出，validated_command 只在六维有限值校验通过后填写；NaN/Infinity 采用结构化对象 {"nonfinite":"NaN"}、{"nonfinite":"+Infinity"} 或 {"nonfinite":"-Infinity"} 保存，和未获取的 null 区分，整个日志严格符合 JSON。previous_sample 单独保存上一成功拍的 tick、time_s 和观测，不会混入本拍字段。保留异常 tick、预期时间、上述现场及此前 CSV，不返回可执行数据。进入运行器后，无论成功或失败最终都将六轴速度目标置零且不再推进物理时间。该停机仅为仿真伺服目标归零，不是硬件急停或停止距离保证。命令写入或物理步发生内部异常时不会重试。

运行 `python scripts/verify_six_axis.py`；需要已编译的三个动态库、NumPy 1.26.4、PyBullet 3.2.7。GitHub Actions 的 Six axis integration 保存逐拍 CSV、异常 JSON 和带源码哈希的 report.json。新的同周期证据位于 results/six-axis-cycle-fix/。故障注入发生于 tick=5（0.10 s）；应有且仅有此前 5 个运动写入，候选/篡改应为 0 个。正常运行若没有时序错误、跳变和异常，也在报告中明确记零。所有验证均为 UR5/PyBullet 动力学仿真，未连接真实机器人。
